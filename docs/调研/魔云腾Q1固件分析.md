# 魔云腾 Q1（RK3588）V3 固件拆解分析

> 2026-11-19。目的：评估把自有「云测机」系统（Redroid + 管家）跑到用户自有的魔云腾 Q1 盒子上的可行性与最优路线。
> 固件来源：官方开源下载中心 `doc.opencecs.com`，`Q1V3-2026.v0.8.9`（`firmware_v3-QL-q1-...-v3.zip`，578MB，id 178）。可随便重下 → 刷回官方即可救砖。

## 硬件 / 启动链
- SoC：RK3588（`parameter.txt` MACHINE_MODEL=RK3588），GPT 分区。
- 存储：SPI/uboot + NVMe 主盘（用户机 512GB 长城 GW3500）。Docker 数据盘挂在 `/mmc`。
- 分区：uboot / env / misc / security / boot(64MB) / recovery / backup / rootfs(~3.75GB) / userdata(grow 占满盘)。
- 固件包内含：`MiniLoaderAll.bin`（RK3588 loader）、`uboot.img`、`boot.img`、`rootfs.img`、`recovery.img`、`misc.img`、`apatch-boot_v2.img`（官方 APatch root 启动镜像）、官方 `刷机工具.exe` + `刷机驱动`（Rockchip rockusb，与我们从 Radxa 下的同源）。

## 系统本体（关键）
- **rootfs = Alpine Linux 3.21.2（aarch64, musl, OpenRC）**，ext4。
- **内核 6.1.141（RK3588 BSP，Android NDK clang 编译）**，带 `/proc/config.gz`(IKCONFIG)。
- **内核已带 `binder` + `binderfs` + `ashmem`**（boot.img 字符串实证：`/dev/binderfs`、`binder rw,max=1048576`、`ashmem` 等）。
  → **结论：我们的 Redroid 在 Q1 硬件上原生可跑，内核层不用自己编。**
- 已预装 **docker / dockerd / containerd / runc**；`daemon.json` data-root=`/mmc`，V2 模式会开放 2375 docker API（V3 用 iptables 封掉）。
- 安卓容器用 **docker-compose** 起；官方镜像是 `registry.cn-hangzhou.aliyuncs.com/whsyf/dobox:*`（他们的「dobox」= docker android）。
- 其它：**Tailscale**（远程）、**RAUC + hawkbit**（A/B OTA 升级）、s6/runit 监督。

## 收费 / 绑定层（要替换掉的）
default runlevel 自启的三个自有服务：
- `mytsvr` → `/usr/bin/mytsvr_v3`（主服务，连云平台/账号绑定；还拉起 `check_sc0prpy.sh`、`myproxy`、`tee-supplicant`）。设备授权校验走 **TEE**（tee-supplicant）。
- `mytgui` → `/usr/share/mytgui/mytOled`（OLED 小屏 + 他们的 Web 管理，自带 docker-compose.yml）。
- `myt_sdk` → `/usr/bin/myt-sdk`。

只要不启动 `mytsvr`，就没人去问 TEE 授权，也不连他的云 → 不产生费用。启动链（loader/uboot/boot/kernel）与这三个服务无关，关掉它们不影响开机。

## root / 访问
- `/etc/shadow` root 为 `$6$` SHA-512 哈希（未知明文）。**无需破解**：改造镜像时直接改 `/etc/shadow` 重置 root 密码 + 打开 `PermitRootLogin yes`、`PasswordAuthentication yes` 即可 SSH 进去。sshd 默认已在自启列表。

## 最优路线：接管底座（低风险）
保留他的 **bootloader + 内核 + 驱动 + docker**，只换 **用户态管理层**：
1. 取官方 `rootfs.img`（ext4）离线挂载改造：
   - `rc-update del mytsvr/mytgui/myt_sdk`（删 `/etc/runlevels/default/` 下三个软链）；
   - 重置 root 密码 + 开 SSH 密码登录；
   - 放入我们的管家（ARM64 单文件）+ OpenRC 自启脚本；
   - 初期可直接复用他已验证的内核/驱动，Redroid 镜像换成我们的。
2. 用 RKDevTool（MiniLoaderAll + parameter + uboot + misc + boot + 改造后的 rootfs）经 MASKROM 刷回。
3. 启动 → SSH 验证 binder / docker → 装/起 Redroid + 管家。

**风险评估**：启动链与内核不动 → 变砖风险很低；任何失败都能用官方 `firmware_v3-QL-q1-v0.8.9` 刷回原样。

## 待确认 / 后续
- 用户机现为 **0.7.8**（旧）；APatch root 工具支持 0.8.5/0.8.7/0.8.9。若走"不刷机 root"旁路需先官方升级；但我们走"改造 rootfs 重刷"不依赖 APatch。
- 是否存在强制 secure-boot 校验 rootfs 签名：从"官方分发非签名式 image + APatch root 可用"推断未强制；实刷前以"先刷仅重置密码的准官方镜像"小步验证。
- GPU：开发测试用软件渲染即可；Mali 透传后续再说（他们开源的 tebox 有 Mali 透传可参考）。

## 成品刷机包已生成并交付（2026-11-19）

已按"接管底座（最小改动）"做出第一版刷机包并送到用户电脑 `D:\RK_Flash\q1pkg\`：

- **基础**：官方 `firmware_v3-QL-q1-2026.v0.8.9`（rootfs 官方 md5 `da27a0a369fee79253f1366feb875268`）。
- **改动（offline 挂 ext4 改，最终"干净版"）**：① `/etc/shadow` root 口令重置为 `cloudtest`（`$6$Qz9xKp2m$...`）；② `sshd_config` 追加 `PermitRootLogin yes` + `PasswordAuthentication yes`；③ **删掉 `/etc/runlevels/default/` 下的 `mytsvr`/`mytgui`/`myt_sdk` 三个自启软链**（开机不再连魔云腾云、不绑账号、不跑其服务；二进制留盘但不启动）。逐文件 diff 确认：干净版 vs 官方**只差这 5 处**（3 个自启软链 + shadow + sshd_config），别无改动；`grep -ri myt` 整个 runlevels 为空。
- **扫描确认**：魔云腾自启只有这 3 个服务，无藏在 cron/local.d/periodic/s6 里的（全查过）。
- **改后 rootfs md5** `deec38685a8d3c3a78094891e04ea7f1`；e2fsck 通过；无 dm-verity/AVB（内核 cmdline 无 verity，RAUC 的 `verity` 仅用于 OTA 包验签，直刷不走这条）。
- **交付方式（踩坑）**：中美国际带宽被限到 ~12KB/s，任何从阿什本直传都慢到不可用。改为：用户电脑加 hosts（`119.96.73.226 doc.opencecs.com mirror.opencecs.com`，opencecs 实为武汉服务器，内网直连 ~1.7MB/s）下官方固件；我只传 **~333KB 字节补丁**（37916 处改动，`rootfs.patch`，经阿什本 NPM `/var/www/html` 走 80 口 http 送达——80 口通且不限速，22/8088/443/81 被 Oracle 或限速挡），在用户电脑上用纯 PowerShell applier 打补丁（无需外部工具：校验官方 md5 `da27a0a3...`→逐字节打补丁→校验改后 md5 `deec3868...`，OK_MATCH）。
- **刷法**：`q1pkg\刷机工具.exe` →「下载镜像」→「执行」（MASKROM）。`official.zip` 留作后悔药。
- **刷后计划**：SSH `root/cloudtest` 验证 binder/docker → `rc-update del mytsvr mytgui myt_sdk` → 装管家 + Redroid。

## 实机刷入成功（2026-11-19）

RKDevTool「下载镜像」→「执行」刷入成功，盒子自动重启进入干净系统。实机验证：

- SSH `root` / `cloudtest` 登录成功，hostname `mytos-pro-q1`（banner 仍显示 "Myt OS Pro!"，只是 /etc/issue 文本，无害）。
- 系统 **Alpine Linux**；**实际运行内核 `5.10.198`**（不是之前 boot.img 字符串里看到的 6.1.141；以 `uname` 为准；RK3588 BSP）。
- **binder 齐全：`/dev/binder1`–`/dev/binder36`（36 个静态 binder 设备）+ `/dev/ashmem`** —— 内核天生为多开安卓容器配置（`CONFIG_ANDROID_BINDER_DEVICES` 静态多设备；注意不是 binderfs 的 binder/hwbinder/vndbinder 三件套，装通用 Redroid 时 binder 设备命名可能要适配）。
- **魔云腾三服务确认未启动**（`rc-status` 无 mytsvr/mytgui/myt_sdk）。
- Docker 27.3.1；但 **dockerd 不在 default 自启**（魔云腾靠自家服务拉起），需 `rc-service docker start` + `rc-update add docker default`。dockerd 默认还开了 `tcp://0.0.0.0:2375`（无认证，局域网暴露，待收紧）。日志有 `memory cgroup not supported` 警告（基本容器能跑，Redroid 待验）。
- 磁盘：`/`=mmcblk0p8 3.5G（rootfs，已 resize）；`/mmc`=nvme0n1p1 469G（docker data-root，含魔云腾旧数据 193G）。
- **盘上留有现成镜像**（RK3588 可用）：`mytos/dobox:Q14_gms/Q14_base`、`tkyds/android:q14_all`、`tkyds/custom:q12/q14`、`whsyf/dobox:alpine` 等——可作实机验证与自建镜像参考。已删除其全部旧容器。
- **交付大坑总结**：中美国际带宽限速 ~12KB/s，阿什本任何直传都不可用；靠给用户机加 hosts（opencecs=武汉 119.96.73.226，内网 ~1.7MB/s）下官方固件 + 仅传 333KB 字节补丁本机打补丁，才把 552MB 的包落到用户机。
