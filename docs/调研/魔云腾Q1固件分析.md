# 魔云腾 Q1（RK3588）V3 固件拆解分析

> 2026-11-19。目的：评估把自有「云测机」系统（Redroid + 管家）跑到用户自有的魔云腾 Q1 盒子上的可行性与最优路线。
> 固件来源：官方开源下载中心 `doc.opencecs.com`，`Q1V3-2026.v0.8.9`（`firmware_v3-QL-q1-...-v3.zip`，578MB，id 178）。可随便重下 → 刷回官方即可救砖。

## 硬件 / 启动链
- SoC：RK3588（`parameter.txt` MACHINE_MODEL=RK3588），GPT 分区。
- 存储：SPI/uboot + NVMe 主盘（用户机 512GB 长城 GW3500）。Docker 数据盘挂在 `/mmc`。
- 分区：uboot / env / misc / security / boot(64MB) / recovery / backup / rootfs(~3.75GB) / userdata(grow 占满盘)。
- 固件包内含：`MiniLoaderAll.bin`（RK3588 loader）、`uboot.img`、`boot.img`、`rootfs.img`、`recovery.img`、`misc.img`、`apatch-boot_v2.img`（官方 APatch root 启动镜像）、官方 `刷机工具.exe` + `刷机驱动`（Rockchip rockusb，与我们从 Radxa 下的同源）。

## 系统本体（关键）
- **rootfs = Alpine Linux 3.21.2（aarch64, musl, OpenRC）**，ext4。
- **内核 6.1.141（RK3588 BSP，Android NDK clang 编译）**，带 `/proc/config.gz`(IKCONFIG)。
- **内核已带 `binder` + `binderfs` + `ashmem`**（boot.img 字符串实证：`/dev/binderfs`、`binder rw,max=1048576`、`ashmem` 等）。
  → **结论：我们的 Redroid 在 Q1 硬件上原生可跑，内核层不用自己编。**
- 已预装 **docker / dockerd / containerd / runc**；`daemon.json` data-root=`/mmc`，V2 模式会开放 2375 docker API（V3 用 iptables 封掉）。
- 安卓容器用 **docker-compose** 起；官方镜像是 `registry.cn-hangzhou.aliyuncs.com/whsyf/dobox:*`（他们的「dobox」= docker android）。
- 其它：**Tailscale**（远程）、**RAUC + hawkbit**（A/B OTA 升级）、s6/runit 监督。

## 收费 / 绑定层（要替换掉的）
default runlevel 自启的三个自有服务：
- `mytsvr` → `/usr/bin/mytsvr_v3`（主服务，连云平台/账号绑定；还拉起 `check_sc0prpy.sh`、`myproxy`、`tee-supplicant`）。设备授权校验走 **TEE**（tee-supplicant）。
- `mytgui` → `/usr/share/mytgui/mytOled`（OLED 小屏 + 他们的 Web 管理，自带 docker-compose.yml）。
- `myt_sdk` → `/usr/bin/myt-sdk`。

只要不启动 `mytsvr`，就没人去问 TEE 授权，也不连他的云 → 不产生费用。启动链（loader/uboot/boot/kernel）与这三个服务无关，关掉它们不影响开机。

## root / 访问
- `/etc/shadow` root 为 `$6$` SHA-512 哈希（未知明文）。**无需破解**：改造镜像时直接改 `/etc/shadow` 重置 root 密码 + 打开 `PermitRootLogin yes`、`PasswordAuthentication yes` 即可 SSH 进去。sshd 默认已在自启列表。

## 最优路线：接管底座（低风险）
保留他的 **bootloader + 内核 + 驱动 + docker**，只换 **用户态管理层**：
1. 取官方 `rootfs.img`（ext4）离线挂载改造：
   - `rc-update del mytsvr/mytgui/myt_sdk`（删 `/etc/runlevels/default/` 下三个软链）；
   - 重置 root 密码 + 开 SSH 密码登录；
   - 放入我们的管家（ARM64 单文件）+ OpenRC 自启脚本；
   - 初期可直接复用他已验证的内核/驱动，Redroid 镜像换成我们的。
2. 用 RKDevTool（MiniLoaderAll + parameter + uboot + misc + boot + 改造后的 rootfs）经 MASKROM 刷回。
3. 启动 → SSH 验证 binder / docker → 装/起 Redroid + 管家。

**风险评估**：启动链与内核不动 → 变砖风险很低；任何失败都能用官方 `firmware_v3-QL-q1-v0.8.9` 刷回原样。

## 待确认 / 后续
- 用户机现为 **0.7.8**（旧）；APatch root 工具支持 0.8.5/0.8.7/0.8.9。若走"不刷机 root"旁路需先官方升级；但我们走"改造 rootfs 重刷"不依赖 APatch。
- 是否存在强制 secure-boot 校验 rootfs 签名：从"官方分发非签名式 image + APatch root 可用"推断未强制；实刷前以"先刷仅重置密码的准官方镜像"小步验证。
- GPU：开发测试用软件渲染即可；Mali 透传后续再说（他们开源的 tebox 有 Mali 透传可参考）。

## 实机联调（2026-11-19，续）

- 建立**自主 SSH 通道**：用户机生成 ed25519 key、用户在盒子 SSH 会话里追加公钥到 `~/.ssh/authorized_keys`；此后从用户机经 DC 以 `ssh -i key root@192.168.68.194` 免密驱动盒子（盒子是内网 IP，云端够不着，DC/用户机是必经桥）。Windows 私钥要 `icacls` 收权限、且 `-N ""` 必须用 `--%` 传空密码短语，否则 OpenSSH 拒用。远端复杂命令走 `type rcmd.sh | ssh ... bash -s`（避免 PowerShell 吃掉 `$`）。
- 盘上镜像架构：`tkyds/android:q14_all`、`tkyds/custom:q14/q12`、`tkyds/*` 为 **arm64**（真安卓）；`mytos/dobox:Q14_gms/base` 为 **amd64**（x86，疑似混入，跑不了）。
- **他的安卓镜像被 DRM 锁死**：`/init` 内置 AVB(vbmeta) 校验 + "v3 环境"检查，非他 mytsvr 搭的 V3 环境启动即 `not in v3 env` 退出。**不走破解路**（无底洞 + 属破解其产品保护）。→ 改用自有 Redroid。
- 系统温度 idle ~43°C；风扇不转（大概率温控，热了再转，待负载时观察/必要时配 PWM 风扇控制）。

## 自有 Redroid 首台跑通（2026-11-19）🎉

在干净系统上成功启动第一台**标准 Redroid**（无魔云腾、无 DRM），`boot_completed=1`：

- 镜像：`redroid/redroid:13.0.0-latest`（经 daemon.json 加 `registry-mirrors: https://docker.m.daocloud.io` 国内加速拉取，1.69GB）。
- **binder 适配（关键）**：此内核无 binderfs、只有静态 `binder1..36`。做法：宿主 `mknod /dev/binder c 10 122`、`/dev/hwbinder c 10 121`、`/dev/vndbinder c 10 120`（即 binder1/2/3 的 major/minor），**并 `chmod 666`**（否则安卓进程 `Opening '/dev/binder' failed: Permission denied` → zygote/servicemanager 崩溃重启）。然后 `docker run -itd --privileged ... redroid/redroid:13.0.0-latest androidboot.redroid_gpu_mode=guest`。
- GPU：先 `redroid.gpu.mode=guest` 软件渲染，启动正常。
- 结果：zygote/surfaceflinger/servicemanager 全 running，桌面起来，apps 收到 BOOT_COMPLETED。adb 映射在宿主 5555。
- 清理：已删前任（二手设备）全部 docker 镜像 + /mmc 非 docker 旧数据目录（data 77G/custom/agent/...），/mmc 从 193G→6.1G（仅剩系统 swapfile）。
