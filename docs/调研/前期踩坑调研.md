# 前期踩坑调研（2026-11-14 联网）

> 本文保留早期技术调研发现，用于识别硬件、驱动、Android 容器接口的兼容问题。研究笔记不等于已经完成的功能，也不代表后续开发任务自动获批；后续实施以最新项目定位、明确测试范围与实际代码为准。

## 底子和显卡（返工风险最高）

1. **官方 Redroid 不支持 RK3588 的 Mali**；社区 CNflysky/redroid-rk3588 只维护 LineageOS 20，AOSP 版停更，**不支持软件渲染（甲骨文跑不了）**，要 Armbian 瑞芯微 6.1 内核 + PSI + binderfs + DMA-BUF + Mali CSF 驱动 + `/lib/firmware` 固件。→ 安卓层的显卡相关在板子上做。
2. LineageOS 底子有痕迹（ro.lineage.*）→ 倾向「瑞芯微安卓 SDK 的 Mali 驱动 + Redroid 本体」（竞品做法）。
3. **Mali 驱动内核版本和用户层 libmali 版本必须配对**（g24p0/g29p1…），固定写进仓库。
4. **`androidboot.redroid_*` 参数会变成 `ro.boot.redroid_*`，App 能读到** → 自己编译镜像改名。
5. 源码分三层：AOSP（公开）、内核（GPL 必公开）、**瑞芯微安卓适配 SDK（看厂家给不给，没有它 Mali 用不了）**。Mali 用户层驱动是闭源二进制，自己做不了；备选全开源栈 Panthor + Mesa（显卡名/功能列表和官方驱动不同，深度检测能看出）。
6. 公开 SDK：Radxa（A12）、研华（A13 内核 5.10.157、**A14 内核 6.1.75**）、飞凌（**A14 内核 6.1.99**）、Firefly（A12 邮件申请）、Radxa ROCK 5C（A14）。**公开渠道没有 RK3588 的 A15/16**。
7. 安卓版本：美国 2026 年 Android 16 约 40%、14 约 8.5%（StatCounter）；全球 16 25.4%、14 15.3%、15 14.7%（谷歌 10 月）。版本号不能只改数字（接口不同会露馅）。

## 内核

8. 配置清单：`CONFIG_PSI=y`（否则 lmkd 开机循环）、binder、binderfs、DMA-BUF heaps、memfd、**4K 页**（Oracle Linux 的 ARM 内核是 64K，Redroid 跑不了）。
9. 每个容器独立 binderfs（已实测：阿什本上每个容器有自己的 `/dev/binderfs`，两台同时跑正常）。
10. 甲骨文换内核救援：Ubuntu 默认隐藏 GRUB，要串口控制台打断；新内核参数必须带串口 console。

## 网络

11. 不用 Redroid 的 `redroid_net_proxy_*`（App 能读到系统代理）。
12. UDP/QUIC 泄露（TikTok 大量用 QUIC）、IPv6、DNS（Redroid 默认 8.8.8.8）都要处理；上线前每台做泄露测试。

## 系统接口和容器运行差异（历史调研记录）

13. 编解码器名 `c2.rk.*` 暴露瑞芯微。
14. scrcpy 注入事件来源和真触摸屏不同 → uinput 虚拟触摸屏。
15. 虚拟 WiFi 用内核自带 `virt_wifi`（Cuttlefish 在用，默认 SSID「VirtWifi」要改）；阿什本内核已有该模块。
16. 至少一个虚拟摄像头。
