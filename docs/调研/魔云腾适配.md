# 魔云腾（MYT）RK3588 盒子：资料和适配清单（2026-11-16 调研）

标注：【确认】官方文档 / 官方开源代码里直接看到；【推断】根据证据推出来的；【未知】没找到资料。到货后第一件事：`bash host/check-board.sh`，把【推断】【未知】的项逐个核实，结论写回这里。

## 一、硬件
- 【确认】RK3588 的是 **C1、Q1、R1S** 三款独立小盒子（R1S 是 RK3588S2）：8 核 2.2–2.4GHz，内存 16G 或 32G，自带 8G eMMC，可加 M.2 NVMe，千兆网口，12V 2A，有 MaskROM 刷机键和串口。Q1 正面有 OLED 小屏。
- 【确认】机箱款：C8（1U，8 张业务板，每张 16G + 256G）、M48（2U，6 板槽，内置 48 口交换机）。
- 【确认】官方说 Q1 每台最多同时开 12 个实例，开 8 个比较稳。
- 【确认】旧版问答页 C1 约 1599 元/台；另按「窗口」收费 3 元/实例/月（一台最多授权 12 个）。
- 【推断】P1 不是 RK3588（客户端里单独的 `cix` 分支、`androidboot.hardware=myt_p1`），不在我们适配范围。

## 二、系统和容器（官方那套）
- 【确认】官方提供 **Ubuntu 22.04** 固件（SSH myt/123456）；MYTOS 用 `ssh user@IP`（密码 myt，`su` 到 root，root 密码 myt）。【未知】内核版本。
- 【确认】2025-12 起的 V3 固件：GKI 通用内核、KVM 隔离、「以内核模块形式实现内核信息仿真」、SELinux 严格模式、支持安卓 16。
- 【确认】Docker 接口在 **2375 端口、没有认证**（官方开源客户端 MYTEdgeClient 直接调 `http://IP:2375/containers/create`）；另有 SDK 接口 8000（C1 还有 8003）。
- 【确认】安卓镜像是自研 `dobox`（`registry.cn-guangzhou.aliyuncs.com/mytos/dobox:…`），启动参数 `androidboot.dobox_*`、`androidboot.hardware=rk30board`，**不是标准 redroid 参数**；安卓 10–16 都有（镜像列表接口 `www.moyunteng.com/api/api.php?type=get_mirror_list2`）。
- 【确认】容器直通：`/dev/mali0`（Mali 官方闭源驱动，不是 panfrost）、`/dev/mpp_service`、`/dev/rga`（硬件编解码）、`/dev/dri`、各种 `dma_heap`（含 `system-uncached-dma32`）、`/dev/ashmem`、`/dev/tee0`。
- 【确认】binder：宿主机预建 `/dev/binderN`，每个实例 3 个（binder / hwbinder / vndbinder）。
- 【确认】容器 privileged 级能力 + `seccomp=unconfined`；网络是叫 `myt` 的 Docker macvlan（每实例一个局域网 IP），没配就 bridge。

## 三、能不能跑我们的管家
- 【确认】能拿到 root SSH、Docker 开着 → 我们的 agent 可以直接在盒子上管容器。
- 【确认】官方文档站自己有 redroid-rk3588 教程，推荐 cnflysky 的镜像 → 官方默认允许用户在 Ubuntu 上自己跑 redroid。
- 【未知】收费卡在客户端还是 dobox 镜像里。用我们自己的镜像（不用 dobox）应该不经过收费。
- 【未确认】有用户说 Q1「官方锁 CPU 了，刷不了其他系统」；Armbian 适配请求还开着，没人报告刷成功。→ **不刷第三方系统，直接用官方 Ubuntu 22.04 固件**，在上面装我们的管家。

## 四、内核
- redroid-rk3588 必须有【确认】：`CONFIG_PSI=y`、`ANDROID_BINDERFS=y`、`BINDER_IPC=y`、`DMABUF_HEAPS`、Mali CSF 驱动和 `/lib/firmware` 固件；6.1 内核还要 `system-uncached-dma32` 补丁，最好 `ARM64_VA_BITS=39`（48 时部分 App 会崩）。
- Armbian rk35xx 6.1 厂商内核配置【确认】：binder/binderfs、PSI、uinput、macvlan/ipvlan、vsock、nf_tables、KVM 都有；**没开 `MAC80211_HWSIM`**。
- 【推断】TIME_NS 在 arm64 默认开；MYT 内核有 ashmem 和预建 binder；hwsim、TIME_NS、lxcfs【未知】。

## 五、普通 RK3588 板子
- 【确认】Orange Pi 5 / 5 Plus / 5 Max 实测能跑 redroid（Armbian 5.10.160 或 6.1.x），Rock 5B 理论上也行。
- 【确认】GPU 只能走 Mali 闭源驱动 + `/dev/mali0`，cnflysky 明确说不能纯软件渲染；用开源 panfrost/panthor 跑安卓容器没找到可用方案。
- 【确认】能用 GPU 的公开镜像：cnflysky `lineage-20`（安卓 13）；AOSP 12/13 版已停更。
- 【推断】MYT 的 dobox 镜像在别的板子上跑不起来（有人在 Rock 5B+ 上试过失败）。

## 六、我们要做的适配（到货前能做的先做）

**2026-11-16 已做完（云上能做的）**：
- `host/setup-board.sh`：预检加了时间命名空间 / hwsim / uinput / 官方 dobox 云机 / 2375 端口；`--install` 一条龙：挡 2375（systemd + nftables，重启后也生效）→ `setup-host.sh` → 拉 cnflysky lineage-20（安卓 13，可用 PP_REDROID_IMAGE / PP_ANDROID_VERSION 换）→ `build-wifi-image.sh` 叠我们的层 → 写板子参数（Mali-G610、gpu-mode host、超卖 2.5 倍、不开直连）→ `install-agent.sh`。
- 管家 `-mem-overcommit`：内存超卖倍数（每台按机型内存记账，8GB 机型 7.45G、12GB 机型 11.2G）。现在板子用 3.6：(23.2-3)×3.6≈72.7G，8 台里带三台 12GB 机型也开得满；实测 7 台（3 台 12GB）把所有 App 各开 3 遍 + 同时看画面，每台实际约 2G，板子最少还剩 7.2G。超卖时开机前还要求机器实际剩 3GB 以上。
- `build-wifi-image.sh` 支持安卓 13：WiFi 是 HIDL 的 wifi@1.0-service、传感器是 sensors@2.1-service.multihal；安卓 13 的传感器插件 vsock 连不上会自己退回 `/dev/goldfish_pipe`（安卓 14 起没这个退回，要打补丁走 `_dprctd`）→ 小助手两个路径都绑。**云上用 redroid 13 实测**：开机正常、6 个硬件传感器有数据、fts_ts 10 点触控屏、多点触控声明、WiFi HAL 起来了。
- 设备直通：我们的容器本来就是 privileged，Docker 会把宿主机 /dev 下的设备（mali0、mpp_service、rga、dma_heap）都给容器，不用另外写。

**到货后要核实**：cnflysky 镜像叠了我们的层还能不能开机（它的 vendor 里有自己的 HAL，可能冲突）、`gpu-mode host` 是不是它要的参数、Mali 在多台手机之间共用的性能、hwsim 模块。
| 项 | 现状 | 要做的 |
|---|---|---|
| 设备直通 | 云上没有 GPU | 板级配置里列出要直通的设备（mali0、mpp_service、rga、dri、dma_heap/*），容器创建时按存在的直通；`gpu-mode=host` |
| binder | 我们每个容器自己挂 binderfs | 板子内核有 binderfs 就沿用；没有就按官方方式分配预建的 /dev/binderN（每台 3 个） |
| 安卓镜像 | redroid 官方镜像（软件渲染）+ 我们的 WiFi/传感器/触摸层 | 换成能用 Mali 的镜像：cnflysky lineage-20（安卓 13）或 dobox；`build-wifi-image.sh` 要加安卓 13（模拟器 arm64 安卓 33 镜像）；dobox 要先看它的 vendor 能不能叠我们的层 |
| 启动参数 | redroid 的 `androidboot.redroid_*` | dobox 用 `androidboot.dobox_*`：板级层做一张参数名对照表 |
| 网络 | 自己的 docker 网络 + tproxy 按 IP 分流 | 保持我们这套（每台走自己的代理）；macvlan 不需要 |
| WiFi | mac80211_hwsim | 内核大概率没有 → 自己编 hwsim 模块（同版本内核源码）；编不了就照旧走有线（自动退回，不影响别的） |
| 开机时长 | 时间命名空间 | `check-board.sh` 查 CONFIG_TIME_NS |
| 内存显示 | lxcfs | apt 装 lxcfs |
| **安全** | — | **2375 端口没认证，局域网里谁都能控制所有手机**：部署时关掉它（Docker 只听本机 unix socket）或防火墙只放行本机 |
| 内存预算 | 每台按机型 8GB 上限、总和不超过物理内存 | 32G 盒子只能开 3 台。官方开 8–12 台是因为每台实际只用 1–2GB → 板子上加「内存超卖倍数」（只影响能同时开几台，手机里显示的还是 8GB） |
| 差异项 | 云上 uname / SELinux / mounts 改不了 | 官方 V3 固件说有「内核信息仿真」模块和 SELinux 严格模式，到货后看能不能直接用上 |

## 魔云腾怎么做「一套固件、几十款机型」（2026-11-23 反推，只读分析板子上的残留和 dobox Q16 镜像）

**机型包 = 真机采集 + 原样回放**。电脑端 `魔云腾-AI\model\*.zip`（27 款）、板子 `/mmc/phoneModel/`：外层 zip 里套一个机型 zip + `cfg.json` + `.kt`（授权）。
机型 zip 里是在真机上用采集工具录的：`device_info.json`（1~2 MB：系统属性、指纹、显卡字符串和扩展列表、传感器、编解码器、电话……带采集时间）、
真机原版 `libc.so`（每款编译号不同，没改过，`ovLibc` 打开就替换）、`cpuinfo`、`auxv`、`vdso_data`、`cpu/` 整个 sysfs 目录、`meminfo`、`mounts`/`mountinfo`/`mountstats`、`bootconfig`、`df` 输出等。
管理程序 `myt-sdk`（Go）导入 / 切换机型包，拷进每台的 `modelData/`；每台的 `cfg.json` 里 overlay 是**正则生成规则**（EMMCID、序列号、android_id、OAID/VAID/AAID/GAID、MAC、蓝牙名……），`baseCfg.json` 还编造通话记录、通讯录、验证码短信、周围 WiFi、定位。

**内核（这块板子现在跑的就是它）**：每个容器一个「myt 命名空间」，`/proc` 下一组只有 root 能写的入口：`utrelease`/`utver`/`uthost`（uname）、`cpuinfo`、`mnts`/`mntinfo`/`mntstats`、`bootid`、`serial_number`、`productname`、`emmcid`/`emmcsd`/`mmcid`、`rndid`、`sdsize`、`memsize`、`hidemap`/`mapinfo`（藏 / 改 /proc/self/maps 里的条目）、`uid`（对哪些 UID 生效）；`ufo` 是不带伪装的真 cpuinfo。
内核函数：`proc_*_write`、`is_container`、`isTarget`、`myTargetUid`、`modify_utsname`、`soc_driver`、`cpublacklist_attr`。另有 `mytfs`（改名的 overlayfs）和每容器一套 SELinux（#135 用的就是它）。
**我们也可以直接用这组入口**（比 pp_mnt 的 kprobe 简单），但它是魔云腾内核独有的，换别家 RK3588 板子就没有。

**容器**（`/mmc/containerTemplate/Q1_V3_v15.json`）：非特权，给一组 cap；透传 `/dev/mali0`、`/dev/dri`、`/dev/mpp_service`、`/dev/tee0`、dma_heap、binder1~3；`/proc/sysrq-trigger` 只读（#136 他们一开始就防了）；seccomp 关；网络走自己的 VPC（tun2socks，规则在 `/mmc/resource/database/data.db`）。

**安卓里**（都跑在自定义 SELinux 身份 `u:r:rfsd:s0`）：`/vendor/bin/runload init_sync`（init 阶段最早跑：把机型数据写进上面那些 /proc 入口、按序列号给内存大小加偏差、处理 rockchip_cpuinfo、替换 libc）；
`sdsh --daemon`（按 `/data/su/binds` 做 bind 挂载）；`wr`（WebRTC 画面串流）；`rfsd 9083`（控制接口，内带自动化 App com.my.rpa）；`fkcam`（假摄像头，Java）；`extservice2`（Java 系统扩展服务）；`ccd` 换掉系统 adbd（ADB 直接 root）。`hides.json` 列出这些要藏的文件。

**显卡**：改了系统的 `libGLESv1_CM/v2/v3.so`（App 调 OpenGL 的那层）：内置 JSON 解析读机型数据；单独处理 glGetString(i)（显卡名 / 版本 / 扩展，滤掉 `GL_ARM_*`）、glGetIntegerv/Floatv/Booleanv/Integer64v、glGetShaderPrecisionFormat、**glReadPixels/glReadnPixels**（旁边是 ro.serialno，推测按序列号给读回的像素加扰动，让每台渲染指纹不同）。
**没改的**：`libvulkan.so` 原样、驱动是 `/vendor/lib64/hw/vulkan.mali.so` 和 `libGLES_mali.so` → Vulkan 读到 Mali-G610 / ARM；OpenCL 也是 Mali 驱动直接答；`/dev/mali0` 透传在容器里。

**结论**：高通机型在 Mali 板子上，「文字层」（属性、文件、OpenGL 字符串和参数）伪装得很全；Vulkan / OpenCL / 驱动文件名 / 设备节点、性能、CPU 实际指令、渲染结果和 Adreno 真机库对不上（扰动只能让每台不同，变不成 Adreno 的）仍然是破绽。
**可借鉴**：①我们的真 Mali 机型，GL_VERSION 是板子驱动的 `v1.g18p0`，真机（天玑）的 Mali 驱动版本号不一样，可以学他们在 GLES 层按机型换成真机的驱动字符串（要真机数据）；②渲染读回加按机身份的轻微扰动，避免所有云手机渲染指纹完全一样（同型号真机本来也一样，要权衡）；③通讯录 / 通话 / 短信 / 周围 WiFi 这类「生活痕迹」。

### 机型和硬件对不上时，魔云腾各类信息怎么处理（2026-11-24，内核符号 + 镜像 + 机型包）

原则：**每一类在 App「读」的那一层截住，换成机型包里的真机数据；硬件实际「干活」的那一面改不了。**

| 对不上的 | 处理办法 | 依据 | 剩下的破绽 |
|---|---|---|---|
| 显卡（Mali 冒充 Adreno） | 改系统 libGLESv1/v2/v3：名字、版本、扩展、数值参数、精度；glReadPixels 按序列号加扰动 | 镜像里改过的 GLES 库 | Vulkan / OpenCL 没改；`vulkan.mali.so`、`libGLES_mali.so`、`/dev/mali0` 都在 |
| cpuinfo | 内核按容器给假 cpuinfo；屏蔽瑞芯微芯片 ID | `my_cpuinfo_op`、`proc_cpuinfo_write`、`rk3588_set_soc_info`；runload `/cpuinfo > /proc/cpuinfo` | 性能差几倍 |
| 核心数 / 分组 | 内核「CPU 黑名单」藏核；机型包带整份真机 `cpu/` 目录叠到 /sys/devices/system/cpu | `cpublacklist_show/store`；包里的 `cpu/` | 藏掉的核还在跑 |
| 指令集 | 换真机原版 libc + 真机 `auxv` | `prctl_set_auxv`；包里 `auxv`、`ovLibc` | 只骗「问」（getauxval），执行没有的指令照样崩 |
| uname | 内核按容器给 | `proc_utrelease/utver/uthost_write`、`modify_utsname` | 6.6 才有的系统调用在 6.1 上没有 |
| 时间 / 开机时长 | 内核加了改时间的 LSM | `time_spoof_lsm` | — |
| 存储 / 内存 / 序列号 | 内核按容器给（内存按序列号加偏差） | `proc_emmcid/sdsize/memsize/serial_number_write` | — |
| 挂载表 / 内存映射 | 内核给假挂载表、藏自己的库 | `proc_mntinfo/hidemap_write`、`gethidemapword` | — |
| 摄像头 | 假摄像头 fkcam（com.huang.fakecam + libfakecam.so，带 Adreno 型号表） | 镜像 | 画面是假的 |
| 编解码器 / 传感器 | 包里带真机列表（mediaCode.json、sensor.json、sensor_etc），推测扩展服务或替换的 HAL 按列表回报 | 机型包 | 实际编码是 c2.rk.*；传感器数据是生成的 |

**对我们**：只选 Mali-G610 机型，「干活」一面天然一致，只需补「读」的一层（CPU 目录 #147、驱动版本号、编解码器 / 传感器列表，用真机采集数据回放）。
要机型多（几十上百款，像魔云腾），就得把非 Mali 机型也按上表做伪装，代价是和魔云腾一样：查 Vulkan、性能、渲染指纹库会露馅。可以分两档：「一致机型」（Mali-G610）和「伪装机型」（其他，面板标风险）。
魔云腾内核的这些 /proc 接口这块板子上能直接用；换别家 RK3588 板子就没有，要靠我们的内核模块。
