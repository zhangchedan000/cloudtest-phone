## 1. 项目是什么

在 ARM 机器上用容器跑多台安卓（Redroid），每台有自己的机型档案和独立代理，用一个网页统一管理。用途：**开发测试**（不做 TikTok，接手的人不要自己带入业务场景）。以后作为 Prism 指纹浏览器（`zhangchedan000/fingerprint-browser`）的一个页面接入。

| 阶段 | 状态 |
|---|---|
| 一：甲骨文阿什本开发机（无显卡，软件渲染）上做通用软件层 | ✅ 完成 |
| 二：RK3588 板子（Mali-G610 显卡、硬件视频编码），正式运行环境 | ⏳ 等用户买板子 |

## 2. 规矩（必须遵守）

- 用户没有明确说「开始 / 做」之前，不动服务器、不装东西、不写代码；查资料、讨论、写记录可以。
- 用中文、大白话（用户不是程序员，懂业务）。
- **新加坡服务器**（`instance-20260730-1622`，跑 Prism 团队服务等）**不要动**。
- **阿什本开发机可以重启，但绝对不能失联**：
  - 换内核用 `grub-reboot` 先试一次，没问题再改默认；动内核前先让用户确认甲骨文串口控制台能连上（ARM 串口 ttyAMA0）。
  - 网络规则只作用于容器网段 10.88.0.0/16，SSH 不走代理；改防火墙要能回滚。
  - 不动：SSH、`desktop-commander-remote`、`keepalive`（防甲骨文回收）、甲骨文自带 agent、Komari。
- 代码、脚本、配置、机型档案全部进仓库；编译全用脚本。部署以 GitHub 为准（服务器每 10 分钟自动同步）。
- 踩坑一解决就记 `踩坑记录.md`；状态有变化就更新本文件。
- 主动想坑、联网查坑，先填坑再做。

## 5. 已知限制

- 阿什本没有显卡：软件渲染、软件编码，画面有延迟，高清码率上不去；显卡相关检测一定显示软件渲染。等板子。
- 「直连（仅开发）」走机房 IP，只能开发测试，**开发机不登录真实账号**。
- 国内直连阿什本延迟约 290 ms、带宽几百 Kbit/s：用域名看画面最好让 `*.peachshop.cyou` 走代理，或者切「流畅」。
- Chrome 第一次打开要用户自己点同意条款、选默认浏览器（用户决定不自动设）。
- 剪贴板对话框只做了接口实测，页面按钮没人在浏览器里点过。
- 机型伪装现状（`host/check-tells.sh` 可随时自检）：已把所有手机设成「锁 bootloader 的正式版」——ro.debuggable=0、build.type=user、build.tags=release-keys、verifiedbootstate=green、flash.locked、veritymode=enforcing、vbmeta.device_state=locked、ro.secure=1（阿什本实测八条全生效、不影响开机）。**改不动的**：`uname()` 系统调用仍返回宿主机内核（只改了 /proc 文件，要做 seccomp）；`ro.hardware` 用启动参数改会开不了机（要编译镜像）；SELinux 状态由宿主机决定（这台没开 SELinux）。**已落地的机型字段**：序列号、androidId、设备名、蓝牙 MAC（settings put，实测 settings get 对上）、电池电量/充电/温度/健康（dumpsys battery）。电池不固定：开机按档案随机值播种，后台每 3 分钟漂移一步（充电往上、用电往下、温度小幅抖动，每台各走各的；battery.go），避免冻在一个固定值反成破绽。**剩下没落地的，都是阿什本阶段做不了的**（实测确认）：WiFi MAC——容器里没有 wlan0 无线网卡，要 WiFi HAL / 镜像层；GAID 广告 ID——没装谷歌服务（用户决定不装），无处落地；存储容量——要给 /data 做限额挂载（df 显示的是宿主机盘）；触控点数——要改虚拟触摸设备描述符；传感器——硬件缺。以上随板子/镜像阶段再做。
- `ro.product.name`：已从 Redroid 默认的 `redroid_arm64_only` 改成机型代号（如 `xaga`，deviceFidelityProps）。附带把主指纹 `ro.build.fingerprint` 里的 redroid 字样也清掉了（Redroid 用新 product name 重拼主指纹）。实测开机正常。
- **破绽自检剩余项（2026-11-15 全面照镜子后的结论，软件层能干净做的已做完）**：
  1. ~~**指纹残留**~~（已解决：9 个分区指纹 / build 属性统一，用真实 stock 指纹）：主指纹还带 `eng.frank...`（incremental），各分区指纹（system/vendor）还是 redroid 默认、和主指纹不一致，`ro.build.host/user` 是 `build1/frank`。填通用假值还是假，**要真机 adb 读真实 build 号才能填对**（和 dpi、新机型的 CPU 识别信息同属「要真机」）。
  2. **内存**：`/proc/meminfo` 显示宿主机 24GB，档案写 8GB。容器实际 cgroup 只给 3GB，伪造成 8GB 会和真实能力矛盾（App 申请大内存就崩，反成破绽，违反 fakefs「不改能力字段」原则）。**要改得先把每台内存上限提到 8GB（服务器能同时跑的手机变少）——资源取舍，待用户决定**。
- **真实指纹进展（2026-11-15）**：改成按安卓版本存真实 stock 指纹（机型档案 `fingerprints` map，从 GitHub 设备树 lineage_*.mk 的 BuildFingerprint 抠，版本必须和手机一致，不符自动回退）。已填真值：POCO X4 GT(14)、Xiaomi 12T(15)、Redmi Note 13 Pro+(15)——这几款指纹彻底真实、无 redroid/eng.*。**待补**：Xiaomi 13T(aristotle)、Nothing 2a(Pacman)、realme GT Neo 3(ossi)——设备树里暂没找到干净的 14/15 stock 指纹，先用镜像值兜底（各分区一致、无 redroid 字样，只是 incremental 是 eng.*）。补法一样：找对应 codename 的 ROM 设备树、grep BuildFingerprint、填进 `fingerprints`。
- **两个待用户决定的点**：① 真机——买一台二手 Mali-G610 机（天玑 8100/8200）用 adb 读真实 build.prop，一次性解决指纹 / dpi / 更多准确机型；② 内存上限——是否把每台从 3GB 提到 8GB（换取内存保真，代价是同时能跑的手机数量下降）。
- 多台服务器只在阿什本上用两个临时管家程序测过（隧道 + 127.0.0.1），还没有真的第二台服务器；第二台要有自己的 HTTPS 域名和口令（页面是 HTTPS，连 HTTP 地址会被浏览器拦）。
- **2026-11-15 实测结论（见踩坑 #37、#38）**：开发机上「每台走自己真实代理」**是通的**——用真实 vless 节点端到端验证，手机出口 IP = 节点 IP（美国），App 层 DNS 也正常；之前一度以为「没通」是测法错了（坏节点 + 容器里用错 DNS，已记进踩坑 #37）。订阅解析已支持自动跟进 proxy-providers（踩坑 #38），贴原始 OpenClash 链接即可出节点；anytls 协议暂不支持。GApps 真谷歌服务原型已验证可行（redroid:14.0.0_mindthegapps）。
- 代理库每台服务器各一份，不同服务器之间不共享（以后并进 Prism 时改用 Prism 的代理库）。
- 机型必须和真实显卡一致（RK3588 = Mali-G610），可选机型不多。

## 6. 用户的决定（接手的人不要改）

- **不做谷歌套件**（Play 商店）：先用 Chrome 下载 APK 装 App，真需要再说。
- **不自动把 Chrome 设成默认浏览器**。
- 机型库删了国行 Redmi K50，只留海外版机型。
- **不显示「一号一 IP」**：一台手机可以挂多个代理切换。
- **先不并进 Prism 启动器**，等稳定了再并；并的时候：Prism 加「云手机」菜单，代理用 Prism 的代理库，去掉云手机自己的代理页，只留 云手机 / 机型库 / 机器。

| 野火鲁班猫 5（备选） | 硬件最合适（M.2 NVMe、风扇、16G）；内核 5.10.160；安卓版本待问 |

公开渠道没有 RK3588 的 Android 15/16 SDK；竞品的 15 是「Mali 驱动 + Redroid 15 本体」。备选路线：联发科 Genio 510（Mali-G57）。

**板子到手后**：
1. 先用厂家自带系统跑 `bash host/check-board.sh`：内核有没有 Redroid 需要的功能（binder / binderfs 等）、Mali 显卡驱动、硬件视频编码，脚本直接给结论。
2. 都满足就**不编译内核**，直接装 Docker + 管家程序；缺了就用厂家 SDK 源码打开开关重新编译（只为驱动和 Redroid 功能，每种板子做一次，脚本进仓库）。
3. 管家程序加 `-gpu-family Mali-G610 -gpu-mode host`，实时画面改用硬件编码，测画质和延迟。
4. 一台板子开几台手机：测内存、CPU、温度，定同时运行上限。
5. 部署方式和阿什本一样：`host/setup-host.sh` → `host/install-agent.sh` → 自动同步；网络模块 `host/network.sh install / apply / confirm`。

## 8. 技术方案（已定）

| 层 | 方案 |
|---|---|
| 安卓 | 官方 Redroid 镜像（14、15）；板子上用「瑞芯微 SDK 的 Mali 驱动 + Redroid」 |
| 管家程序 | Go 单文件（ARM64），Docker API 管容器，内嵌管理页（`agent/`） |
| 管理页 | React 19 + Ant Design 6（`web/`，主题照搬 Prism，以后合进 Prism） |
| 网络 | 宿主机 mihomo 透明代理，按容器 IP 分流；DNS 也走代理；手机里不出现代理网卡；每台独立代理（可挂多个切换） |
| 机型 | 必须和真实显卡一致（RK3588 = Mali-G610）；档案在 `profiles/` |
| 操作 | 点击滑动用 `input`，中文用剪贴板 + 粘贴键（不装 ADB 键盘）；画面用 screenrecord H.264 |
