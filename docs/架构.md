# 架构原则

改代码前先读这一页。

## 教训（来自指纹浏览器）

1. 先用别人的内核、后换官方内核 → 做了两遍。**前期把路线定死再做。**
2. 开发时依赖了 Win11 才有的东西，Win10 上缺一堆 → **不依赖开发机的特殊环境。**
3. 没写记录，改过的问题又重做 → **踩坑当场记，代码全进仓库，编译全用脚本。**

## 七条原则

1. **通用层和硬件层分开**
   - 通用层（换硬件直接复用）：`agent/`、`web/`、`profiles/` 的格式、`host/`。
   - 板级层（`boards/<板子>/`）：内核源码来源、显卡驱动版本、编译参数、安卓底子。
   - 换芯片 = 加一个 `boards/` 目录 + 一批匹配新显卡的机型档案，然后整体重测。
2. **每个机型可能不同的东西全写成配置（机型档案）**，不写死在代码里。档案格式带版本号。
3. **能放在我们自己代码里的，不依赖硬件或系统自带的**；只有显卡驱动这类真绑硬件的放板级层。
4. **不依赖开发机的特殊环境**：目标是通用 ARM64 Linux（Ubuntu/Debian），依赖写进 `host/` 安装脚本自动检查安装。
5. **依赖要写下来、查出来**：启动先做环境自检，缺什么明确提示怎么补。
6. **尽早在两种环境上跑**（甲骨文 + RK3588）。
7. **留扩展接口，不提前做功能**。

## 沿用 Prism 的规矩

- **一份定义，到处引用**：代理库、分组库、机型库各存一份，设备只存引用（`proxyId`、`groupId`、`modelId`）+ 手动改过的字段。
- 颜色只在一个地方定义（主题 tokens）。
- **代理缺失或不可用 → 禁止开机，绝不退回真实网络。**

## 结构

```
浏览器 / Prism ──HTTPS(登录)──> 管理页(web) ──接口+画面通道──> 管家程序(agent, 每台机器一个)
                                                                     │
                                                              安卓容器 × N
```

- 画面：安卓采集 → H.264 → agent → WebSocket → 浏览器 WebCodecs 解码。
- 操作：浏览器 → agent → 容器内 uinput 虚拟触摸屏/键盘（不用注入，不在安卓里装辅助 App）。
- 网络：宿主机 mihomo 透明代理，只作用于容器网段；宿主机自身（SSH、DC）不走代理。UDP/QUIC、IPv6、DNS 都要处理。

## 容器系统信息文件视图适配（甲骨文阶段不改内核）

| 接口或文件 | 当前实现与后续计划 |
|---|---|
| `/proc/version`、osrelease、cpuinfo、midr_el1、CPU 频率 | 已有代码按机型档案生成替代内容，在容器开机后通过 bind mount 提供对应读取视图；并非修改宿主机内核 |
| meminfo、uptime | 在早期技术计划中列出，尚须对照现有代码核实是否实现 |
| `uname()` 系统调用 | 曾规划研究 seccomp 用户通知方案，尚未确认为已实现；具体行为和适用场景需单独评估 |
| `mrs MIDR_EL1` 指令 | 如需改变底层指令行为，必须在后续内核/板级适配阶段研究、构建和验证 |

**原则**：区分“容器内文件视图调整”和“内核源码修改”；每一项明确代码、单测、实机验证状态。保留历史实现与测试记录，避免仅依据模块名称判断其功能。
