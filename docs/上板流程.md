## 换新板快速流程（一条龙，不碰代码 / 不重编译）★首选

> 2026-11-20。整条路已在魔云腾 Q1 实战跑通（SIM、Mali 显卡、拨号短信、Google Play、身份唯一、指纹干净全齐）。
> **以后再拿到同一款 Q1（或同内核的 RK3588 盒子），照这张表走就行，全程不写代码、不重编译**——重活都成了现成复用件。
> **唯一可能要重编的**：新板**内核版本和当前不一样**时，防破绽内核模块 pp_mnt/pp_uts 要按新内核重编（阶段9）；**同款 Q1 同固件内核一样，这步也免**。

**现成复用件（已备好，别再从头做）**：

| 件 | 位置 | 用法 |
|---|---|---|
| 刷机固件 | 用户电脑（Q1 Alpine 固件 + RKDevTool，见 `调研/魔云腾Q1固件分析.md`） | MASKROM 刷机 |
| 管家二进制 | GitHub `tools/dist/prism-phone-agent-arm64.gz` | `wget` 即得，**不用编译** |
| 安卓完整镜像 | `/mmc/pp-dist/android13-full.tar.gz`（含 SIM/显卡/拨号短信/Google/干净指纹的最终镜像 `lineage-20-wifi-tel-resign-apps`） | `docker load` 即得，**不用重编** |
| 板子配置 | `/mmc/pp-dist/board-setup.tar.gz`（init.d/local.d/sysctl/风扇脚本，含已配好的 agent 启动参数） | 解到 `/` 即得 |
| 全部脚本 | `git clone https://github.com/zhangchedan000/prism-phone.git` | `host/*.sh` |

> 换板前先从当前板子把 `/mmc/pp-dist/` 整个拷走（scp / U 盘），这是复用件的家。

**步骤**（SSH 进新板，root）：

1. **刷机**：MASKROM（按住 recovery 键通电）+ RKDevTool 刷 Q1 固件 → 进 rootfs 改 root 口令 + 开 sshd → SSH 进去。
2. **基础**：装 docker 并自启（`rc-update add docker default`）；data-root 指 `/mmc`；`/etc/docker/daemon.json` 加国内镜像加速；apk 换阿里源。清前任 docker 数据（二手盒子）。
3. **binder**：解 `board-setup.tar.gz` 的 `/etc/local.d/binder-nodes.start`（已写好 mknod binder/hwbinder/vndbinder minor=122/121/120 + chmod 666），`rc-update add local default`。
4. **风扇**：`board-setup.tar.gz` 的 `/usr/local/bin/fan-control.sh` + local.d（Q1 风扇在 pwmchip1）。
5. **导入安卓镜像**：`gunzip -c /mmc/pp-dist/android13-full.tar.gz | docker load`（没 tarball 才跑 `host/build-{wifi,telephony,resign,apps}-image.sh` 重做，慢，见阶段8）。
6. **装管家**：`wget` GitHub 的 gz → `gunzip` 到 `/opt/prism-phone/prism-phone-agent` → 解 `board-setup.tar.gz` 的 `/etc/init.d/prism-phone-agent`（已配好 `-images 13=...-resign-apps`、`PP_TOKEN`、`-gpu-family Mali-G610 -gpu-mode host`、`-redir` 等）→ `rc-update add prism-phone-agent default`。
7. **网络/代理**：装 mihomo（`/etc/init.d/prism-phone-mihomo`）+ 填代理订阅 + `/etc/local.d/pp-redir.start`（REDIRECT 模式，踩坑 #102）+ `/etc/sysctl.d/99-pp-redir.conf`。
8. **DC 直连（可选）**：`/etc/init.d/desktop-commander-remote`（板子自挂 DC，电脑关机也能连，踩坑 #96）。
9. **启动 + 验收**：`rc-service prism-phone-agent start` → 网页 `http://板子IP:8099` 填 token → 建手机开机。三条验收命令：
   ```sh
   docker exec pp-<id> getprop gsm.sim.state                       # = LOADED
   docker exec pp-<id> sh -c 'dumpsys SurfaceFlinger|grep GLES:'   # = ARM Mali-G610
   docker exec pp-<id> sh -c 'getprop|grep -icE "redroid|flysky|lineage"'  # = 0
   ```

> **想更省事**：步骤 2~8 可整理进一个 `host/setup-board.sh`（现有版是预检+Debian 接管，Q1/Alpine 的实际步骤按上面来，可后续补成一键）。镜像也可 `docker tag` 到自己的 Docker Hub / 私有仓库 push，新板直接 `docker pull`，免拷 tarball。

## 阶段 0：准备 / 连接
- 连接方式：USB-C 进 MASKROM（按住板上 maskrom/recovery 键通电）+ RKDevTool 刷机；日常用 **SSH**（给板子装公钥免密，便于远程驱动；Windows 侧私钥记得 `icacls` 收权限、`ssh-keygen -N ""` 用 `--%` 传空密码）。
- 远端跑复杂命令：`type rcmd.sh | ssh root@板子IP bash -s`（避免 PowerShell 吃掉 `$`）。

## 阶段 1：刷/装一个「内核带 binder」的干净 ARM64 Linux
- **目标**：一个能开机、驱动齐、**内核开了 `CONFIG_ANDROID_BINDER_IPC`+`ashmem`** 的 Linux（Alpine/Debian/Armbian 都行）。
- 标准开发板：直接刷官方 Armbian/Debian（NVMe/eMMC/SD）。Q1：刷厂商 Alpine 固件后在 rootfs 里只改 `/etc/shadow`(置 root 口令)+`sshd_config`(开 SSH)、删厂商自启服务（见 Q1 文档）。
- 刷完 SSH 进去，确认：
  - `uname -a`（记内核版本，后面编模块要对上）；
  - `ls /dev/binder* /dev/ashmem`；
  - `zcat /proc/config.gz | grep -iE 'BINDER_IPC|BINDERFS|BINDER_DEVICES'`。
    - 有 `BINDERFS=y` → Redroid 最省事（容器内自动 binderfs）；
    - 只有静态 `BINDER_DEVICES="binder1,...,binderN"`（Q1 是 1..36，无 binderfs）→ 走阶段 3 的 mknod 适配。

## 阶段 2：Docker + 国内加速
- Docker 装好并开机自启（Alpine：`rc-service docker start; rc-update add docker default`；dockerd 加载大数据盘慢，自启脚本要「等就绪」再用）。
- data-root 放大盘（Q1 放 `/mmc`，NVMe；根分区只有几个 G 别放这）。
- **国内拉镜像加速**：`/etc/docker/daemon.json` 加 `"registry-mirrors": ["https://docker.m.daocloud.io"]` 重启 docker。
- Alpine apk 慢就切 `mirrors.aliyun.com`（`sed -i 's#dl-cdn.alpinelinux.org#mirrors.aliyun.com#' /etc/apk/repositories`）。
- （二手/旧板）清前任 docker 数据：`docker rm -f $(docker ps -aq)`、`docker system prune -a --volumes -f`、删 `/mmc` 下非 docker 的旧目录（留 swapfile 和 docker 自己的目录）。

## 阶段 3：binder 适配（仅「无 binderfs」的板子，如 Q1）
- 宿主建标准 binder 设备名指向静态 binderN，并 **chmod 666**（不加 666 安卓进程 `Opening '/dev/binder' failed: Permission denied`，zygote 崩溃重启）：
  ```sh
  mknod /dev/binder    c 10 <binder1的minor>
  mknod /dev/hwbinder  c 10 <binder2的minor>
  mknod /dev/vndbinder c 10 <binder3的minor>
  chmod 666 /dev/binder /dev/hwbinder /dev/vndbinder
  ```
  Q1：binder1/2/3 的 minor = 122/121/120。写进 `/etc/local.d/binder-nodes.start`（`rc-update add local default`）持久化。
- **多开**：`--privileged` 的容器都共享宿主 `/dev/binder`（binder1），**多台会抢同一个 binder 冲突**。多开要每台分不同 binder（binder1/2/3 给机1、binder4/5/6 给机2…，N 个给 ~N/3 台）。做法：管家给每台分配 binder 序号，经 pp-init/InitHelper 在容器内把对应 binderN 绑成 `/dev/binder`（**待在管家里实现**）。binderfs 的板子无此问题。

## 阶段 4：验证 Redroid 单台（先证明硬件能跑）
```sh
docker pull redroid/redroid:13.0.0-latest
docker run -itd --name r1 --privileged -v /mmc/r1_data:/data \
  redroid/redroid:13.0.0-latest androidboot.redroid_gpu_mode=guest
# 等 ~40s
docker exec r1 getprop sys.boot_completed   # =1 即成功
```
Q1 实测 `boot_completed=1` ✓。确认后删掉 r1，交给管家管。

## 阶段 5：部署管家（web 自带、做成服务）
- 管家是 `CGO_ENABLED=0 GOARCH=arm64` **单静态二进制，网页打包在内**（`bash agent/build.sh`）。
- 送上板：仓库 `tools/dist/prism-phone-agent-arm64.gz`（板子 `wget` GitHub raw 直接拉，国内可达）；或板子 `apk add go git` + goproxy.cn 自编。
- 启动（测试机直连、软件渲染）：
  ```sh
  export PP_TOKEN=<自定令牌>
  prism-phone-agent -listen 0.0.0.0:8099 -data /mmc/pp-data \
    -gpu-family software -gpu-mode guest \
    -images 13=redroid/redroid:13.0.0-latest \
    -dev-host -max-running 4 \
    -no-wifi -no-sensors -no-host-guard -no-timens
  ```
  - **监听 0.0.0.0 必须设 `PP_TOKEN`**（否则拒启）；网页里填一次令牌登录。
  - **`-dev-host`**：允许「直连(仅开发)」，否则「没分配代理禁止开机」。建手机时 `proxyId=direct-dev`。
  - 板子正式用时上网络模块（mihomo）走代理，不用 `-dev-host`。
- 做成 OpenRC 服务开机自启（**待补：写 `/etc/init.d/prism-phone-agent`**）。
- 浏览器开 `http://板子IP:8099` → 填令牌 → 创建手机 → 开机 → 看屏幕。Q1 实测全链路通 ✓。

## 阶段 6：散热 / 风扇
- 板子多半有 pwm-fan（设备树里，`/sys/class/hwmon` 有 pwm 或 thermal cooling device，内核自动温控）。
- Q1 特殊：内核没风扇驱动，风扇在 `/sys/class/pwm/pwmchip1`，魔云腾用用户态控。解法：写温控脚本（读 `thermal_zone0/temp`，按档位写 `pwm0/duty_cycle`）+ `/etc/local.d` 自启（已装 `/usr/local/bin/fan-control.sh`）。
- 判断风扇在哪个 pwmchip：逐个 export + 开满 duty，看哪个一开风扇转（Q1 是 pwmchip1）。

## 阶段 7：GPU 硬件加速（提性能，先软件渲染够测试）
- 先 `-gpu-family software -gpu-mode guest`（SwiftShader，能跑、不流畅）。
- RK3588 Mali-G610 硬件加速：`-gpu-family Mali-G610 -gpu-mode host`，需要 Redroid 镜像里带对应 Mali 用户态驱动/HAL + 宿主 `/dev/mali0`、`/dev/dri`。

### Q1 实测验证（2026-11-19，硬件加速已证明可行）
- **方针（和用户定）**：复用魔云腾的「硬件驱动层」（内核 Mali 驱动 `g18p0`、`/lib/firmware/mali_csffw.bin`、`/dev/mali0`、`/dev/dri`、`/dev/dma_heap`），甩掉其云锁/收费层；安卓用**干净底子**（开源 Mali 镜像），按需从魔云腾镜像扒板级配置，不整体复用其 DRM 锁死的 android 镜像。
- **现成可用镜像**：`cnflysky/redroid-rk3588:lineage-20`（LineageOS 20=安卓13，2.19GB，自带 `libGLES_mali.so` 42MB）。用户态版本 **`g18p0-01eac0` 和 Q1 内核驱动完全一致**。
- **实测**（魔云腾 Q1、内核 5.10.198、无 binderfs、静态 binder）：
  ```sh
  docker pull cnflysky/redroid-rk3588:lineage-20   # daocloud 镜像加速，很快
  docker run -d --name mali-test --privileged -v /mmc/mali-test-data:/data \
    cnflysky/redroid-rk3588:lineage-20 androidboot.redroid_width=720 androidboot.redroid_height=1280
  # ~50s boot_completed=1；dumpsys SurfaceFlinger：
  #   GLES: ARM, Mali-G610, OpenGL ES 3.2 v1.g18p0-01eac0...   ← 真硬件 Mali，不是 angle/软件
  ```
  前置条件 Q1 全满足：`/lib/firmware/mali_csffw.bin`、`/dev/dma_heap/{cma,system,...}`、`/dev/mali0`、`/dev/dri/{card0,card1,renderD128,renderD129}`。`--privileged` 容器直接访问，无需显式 `--device`。
- **接进管家要做的（整合，尚未做）**：
  1. **机型档案加 Mali-G610 的**：管家有「显卡一致性守卫」（`service.go` gpu-mismatch）——一旦机器 `-gpu-family Mali-G610`（非 software），只有档案 `gpuFamily=Mali-G610` 的机型能建；`gpu-mode host` 下安卓看到的是**真 Mali**，没法再伪装成别的显卡。所以要备 Mali-G610 机型档案（天玑 8100/8200、Tensor G2 这类用 Mali-G610 的真机）。
  2. **镜像接入**：`-images <ver>=cnflysky/redroid-rk3588:lineage-20`（或在其上做我们的定制，见阶段8）。
  3. **开正式渲染**：`-gpu-family Mali-G610 -gpu-mode host`。设非 software 后网页显卡显示真 Mali、「软件渲染/不要登录真实账号」提示自动消失。
  4. **去 dev-host**：配 mihomo + 真代理（`-mihomo-api`），去掉 `-dev-host`，否则「没代理禁止开机」。这步需要用户给代理节点。
- 魔云腾自家 android 镜像（tkyds/android）也带为这块板调好的 Mali + 传感器/RIL，但 `/init` 有 AVB+「not in v3 env」云锁、且带私货，不整体复用；缺啥时从中扒具体板级配置文件。

## 阶段 9：防破绽（最后做，让安卓更像真机）
到这一步「能跑、能管」已完成，再上防破绽。这部分是**原有「换板子迁移清单」**的内容，照 `架构.md` 走：
- 大部分身份字段 fakefs 自带、换板不变（A）；`/data` 来源盘动态读（B）。
- **唯一跟内核绑、换板必做**：按板子内核头文件重编 `pp_mnt`/`pp_uts`（`host/build-kmod.sh`），对不上的内核符号找等价替换，走「防失联」流程加载，`host/check-tells.sh` 复验（C）。
- 板子是真 RK3588，SELinux Enforcing、真 Mali、真 ARM 能力位 → 很多 VM 上的权宜之计（SwiftShader、QEMU 设备、EACCES 补丁）自然消失，比开发机服务器更接近真机（D/E）。
