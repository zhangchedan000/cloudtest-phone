# 踩坑记录

> 问题一解决就当场记。开工前先搜这里。前期调研出来、还没实际遇到的坑见 `调研/前期踩坑调研.md`。

格式：现象 / 原因 / 解决办法（改了什么、在哪）/ 怎么验证

---

### 1. 从用户电脑连云手机 ADB 失败（2026-11-11、11-14）
- **现象**：`adb connect` 报 failed to connect，或 devices 显示 offline。
- **原因**：用户电脑走代理，出口 IP 不固定，不在云手机平台的 ADB 白名单里。
- **解决**：从美国服务器 38.49.55.5（用户电脑上 ssh 别名 `us-site`，adb 在 `/opt/platform-tools/adb`）连，该 IP 已在 DuoPlus 白名单。MoreLogin 不用白名单，但要先 `adb -s 地址 shell <连接码>` 登录。
- **验证**：`adb devices` 显示 device。

### 2. 新机器 apt 被锁（2026-11-14，阿什本）
- **现象**：`Could not get lock /var/lib/apt/lists/lock. It is held by process 88864 (apt-get)`。
- **原因**：一个 `apt-get update` 卡了 106 天（`ps -p <pid> -o etime` 看到 106 天）。
- **解决**：只是 update（不是在装包）可以直接 `kill`，然后 `dpkg --configure -a`。之后 unattended-upgrades 在装 104 个更新又占锁 → **正在装包的不能杀**，用 `systemctl stop unattended-upgrades` 让它装完当前包后体面退出。
- **验证**：apt 能正常运行。`host/setup-host.sh` 里已加「等待 apt 锁」逻辑。

### 3. Desktop Commander 远程连接失败：native WebSocket not found（2026-11-14）
- **现象**：`desktop-commander remote` 报 `Device startup failed: Node.js detected but native WebSocket not found`。
- **原因**：Ubuntu 24.04 软件源的 Node.js 太老，DC 需要 Node 22+。
- **解决**：`apt remove nodejs npm` → `curl -fsSL https://deb.nodesource.com/setup_22.x | bash - && apt install -y nodejs` → 重装 DC。
- **验证**：`node -v` 是 v22，DC 显示 connected。

### 4. DC 设备绑到了错误账号（2026-11-14）
- **现象**：终端显示连接成功，但 AI 这边设备列表里没有，调用报 `not found for this account`。
- **原因**：浏览器授权时登录的 DC 账号和 AI 连接的 DC 账号不是同一个。
- **解决**：`npx @wonderwhy-er/desktop-commander@latest remote --logout`，浏览器换成正确账号（设备列表里能看到 iStoreOS 那个），重新 `desktop-commander remote` 授权。
- **验证**：AI 的设备列表出现新机器。

### 5. DC 后台常驻（2026-11-14）
- 前台运行的 DC 关终端就断。做成 systemd 服务 `/etc/systemd/system/desktop-commander-remote.service`（ExecStart=`/usr/local/bin/desktop-commander remote`，Restart=always，enable）。
- **坑**：用 DC 自己去切换（停前台、起服务）时，要用 `systemd-run --on-active=5` 延迟执行，否则命令执行到一半连接就断了；`pkill -f` 的匹配串要写成 `desktop-commande[r] remote`，免得把自己杀掉。
- **坑**：用户手动在终端又跑了一个前台 DC → 同一设备两个实例，要让用户 Ctrl+C 掉前台那个。

### 6. Redroid 启动参数改属性的限制（2026-11-14 实测，Android 14 官方镜像）
- **能改**：`ro.product.model`、`ro.product.brand`、`ro.serialno` 等 `ro.*` 属性，以及 `androidboot.redroid_width/height/dpi`。直接写在容器启动参数里（`ro.xxx=yyy`）。
- **不能改 1**：**值里有空格会被截断**（`"ro.product.marketname=POCO X4 GT"` 结果是 `POCO`）。截断比不改更糟（前后矛盾）→ 管家程序不传带空格的值，标「待实现」，以后改用 build.prop 方式写入。
- **不能改 2**：`persist.sys.timezone` 这类 `persist.*` 用启动参数设不进去（实测还是 GMT）→ 要开机后设置。
- 代码：`agent/internal/phones/service.go` 的 `resolve()`；测试 `TestStartCreatesContainerWithProps`。

### 7. npm install 崩溃：Cannot read properties of null (reading 'edgesOut')（2026-11-14）
- **原因**：npm 10.9 处理 vitest 4.1 的可选 peer 依赖时的 bug。
- **解决**：`web/.npmrc` 加 `legacy-peer-deps=true`。

### 8. Ant Design 两个汉字的按钮自动加空格（「打 开」）
- 显示别扭，Playwright 按文字找不到按钮。`main.tsx` 里 `<ConfigProvider button={{ autoInsertSpace: false }}>`。

### 9. 这个云端会话不能新建 GitHub 仓库、不能直连服务器
- 新建仓库被拒（403，会话只能访问已接入的仓库）→ 让用户在网页上建，再 add_repo。
- 云端会话出网只有 HTTPS（22 端口不通），不能 SSH/ADB → 操作服务器全靠 DC；往服务器传代码只能通过 DC 写文件（base64 分段 + sha256 校验），或者让服务器从 GitHub 拉。

### 10. Docker 29 要求接口版本 ≥1.44（2026-11-14）
- **现象**：管家程序开机报 `client version 1.43 is too old. Minimum supported API version is 1.44`。
- **原因**：`agent/internal/docker/client.go` 写死了 `/v1.43/` 前缀；Ubuntu 24.04 的 docker.io 是 29.x。
- **解决**：请求路径不带版本号（`http://docker/containers/...`），用守护进程自己的版本。
- **验证**：集成测试 `host/itest.sh` 开机通过。

### 11. 用 DC 执行 `pkill -f` 把自己杀了
- `bash -c '... pkill -f "host/itest.s[h]" ... host/itest.sh ...'`：方括号技巧只防「pkill 自己」，**防不了同一条命令行里后面出现的原字符串**，结果 bash -c 进程自己被匹配杀掉，后面的命令没执行。
- **解决**：按进程名精确杀 `pkill -x <进程名>`（进程名最长 15 个字符，`prism-phone-agent` 要写 `prism-phone-age`），或者先 `pgrep` 拿 PID 再 `kill`。
- **11-15 又踩一次（变种）**：写了个「等测试跑完再更新」的循环 `while pgrep -f host/itest-ap[i]; do sleep 5; done; …; bash host/itest-api.sh`，同一条命令行后面就有 `host/itest-api`，循环永远等自己，卡死。**等别的任务结束不要用 pgrep -f 匹配命令行**：要么让前一个任务结束时自己接着跑下一步，要么用 systemd 单元（`systemctl start --wait` / oneshot）串起来。

### 12. 改 ro.hardware / ro.board.platform 导致开不了机（2026-11-14 实测）
- **现象**：容器起来了，但 `sys.boot_completed` 一直为空，`dumpsys connectivity` 找不到服务；日志 `composer@2.1-service: failed to open framebuffer device`，SurfaceFlinger 反复重启。宿主机连 ADB 报 `No route to host`（因为安卓网络服务没起来，路由规则只有 `from all unreachable`）。
- **原因**：把芯片型号同时写进了 `ro.hardware`、`ro.board.platform`。安卓按这两个名字找硬件驱动（HAL），改成 MT6895 就找不到显卡合成驱动。
- **解决**：「芯片型号」只写 `ro.soc.model`；`ro.hardware`/`ro.board.platform` 单独一个字段 `boardPlatform`，标「后期·需编译镜像」（编译时连 HAL 文件名一起改）。测试 `TestStartCreatesContainerWithProps` 加了断言。
- **排查技巧**：ADB 连不上时用 `docker exec <容器> getprop ...`、`docker exec <容器> logcat -d` 直接看安卓内部。

### 13. 容器在跑 ≠ 安卓开机完成（2026-11-15 实测）
- **现象**：开机接口马上返回，紧接着发按键报 `cmd: Can't find service: input`；截屏能拿到图（开机动画），但操作全失败。
- **原因**：Docker 容器一启动就算「运行中」，安卓 system_server 还要一两分钟才起来。
- **解决**：状态分三种：已关机 / 开机中 / 运行中。`getprop sys.boot_completed` 为 1 才算运行中（按容器启动时间记住，每次开机只问一次）；开机中能截屏看画面，操作返回「还在开机」。时区、语言也在开机完成后才设置。

### 14. 往阿什本传代码很费 DC 额度（2026-11-15）
- 云端会话不能 SSH，服务器拉不了私有仓库，只能用 DC 写文件：每次最多 50 行，base64 二进制靠 AI 逐字抄写不现实。
- 当时的做法：只传改动的纯文本源码（新文件直接写、小改动在服务器上用 sed），再在服务器上 `bash build.sh` 编译。
- **根本解决（待用户操作）**：给阿什本一个**只读**的 GitHub 访问权限（仓库 Deploy key 或只读 fine-grained token），以后服务器直接 `git pull` 再编译。

### 15. 开机完成后安卓框架还会重启一次（2026-11-15 实测）
- **现象**：`sys.boot_completed=1` 之后立刻发按键，报 `Failure calling service input: Broken pipe`、`Can't find service: input`。
- **原因**：开机后设置语言（`persist.sys.locale`）要 `setprop ctl.restart zygote` 重启安卓框架，这几秒 input 服务不在；而 `sys.boot_completed` 一直是 1。
- **解决**：「运行中」= `sys.boot_completed` 为 1 **并且** `service check input` 显示 found；框架重启后忘掉开机记录，等它重新就绪才把「开机后设置」标为完成。

### 16. docker cp 进 /sdcard 失败（2026-11-15 实测）
- **现象**：`Could not find the file /sdcard/DCIM/Camera in container`。
- **原因**：/sdcard（/storage/emulated/0）是安卓 vold 自己挂的虚拟目录，在容器文件系统里不存在；`docker exec mkdir` 走的是安卓的视图，`docker cp` 走的是容器文件系统。
- **解决**：cp 到真正存放的位置 `/data/media/0/...`，再 `chown media_rw:media_rw`，然后让媒体库扫描 `/sdcard/...` 路径。

### 17. systemd 里编译失败：module cache not found（2026-11-15 实测）
- **现象**：自动同步（systemd 定时任务）调 install-agent.sh 编译，报 `go: module cache not found: neither GOMODCACHE nor GOPATH is set`；手动在终端跑没问题。
- **原因**：systemd 服务没有 HOME 环境变量，Go 和 npm 都靠它找缓存目录。
- **解决**：install-agent.sh 开头补上 HOME、GOPATH、GOCACHE；定时任务的 service 里也写 `Environment=HOME=/root`。管家程序更新失败会自动换回旧版，所以这次没有影响运行。

### 18. nftables 链名用了关键字 tproxy（2026-11-15 实机）
- **现象**：`host/network.sh apply` 报 `syntax error, unexpected tproxy`，规则没加上。测试脚本按设计立刻撤销并关掉网络模块，服务器、SSH 不受影响。
- **原因**：`chain tproxy { … }`，tproxy 是 nftables 的关键字。
- **解决**：链名改成 pp_dns / pp_tproxy / pp_forward；apply 前先 `nft -c` 检查语法，不对就什么都不改。
- **测试也要改**：开发机用直连，出口 IP 本来就等于服务器 IP，「出口 IP 对」不能证明流量经过了网络模块。改成开一条慢连接，在 mihomo 的连接列表里找这台手机的 IP。
- mihomo v1.19.34 linux-arm64 包的 sha256：daaf78a6240a282cdfd75bcbf98fe321f6bd52765cc29e79f344191198f0b50f

### 19. tproxy 规则报 No such file or directory（2026-11-15 实机）
- **现象**：`nft -c` 报 `Could not process rule: No such file or directory`，指着 `tproxy to 127.0.0.1:7893`。
- **原因**：内核里有 `nft_tproxy` 模块（`/lib/modules/…/nft_tproxy.ko.zst`），但不会自动加载；`nft -c` 检查时也要用到它。
- **解决**：`host/network.sh apply` 先 `modprobe nft_tproxy nft_socket nft_nat nft_chain_nat`（DNS 改写的 dnat 也要 nft_nat，第三轮实机才暴露），并写进 `/etc/modules-load.d/prism-phone.conf` 开机自动加载。tcp、udp 分两条规则写，兼容 Ubuntu 24.04 的 nftables 1.0.9。
